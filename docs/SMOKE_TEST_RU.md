# Smoke-test с реальным VK-сообществом

Это проверка прежнего бота на Codex SDK, а не подключения к существующим задачам
десктопа. Для нового контура см. [README](../README.md).

## 1. Подготовка

В сообществе VK должны быть включены:

- сообщения сообщества;
- Bots Long Poll;
- событие `message_new`;
- токен сообщества с правом работы с сообщениями.

Создайте тестовый workspace внутри разрешённого корня:

```bash
mkdir -p ./workspaces/smoke-repo
cd ./workspaces/smoke-repo
git init
printf '# Smoke repo\n' > README.md
git add README.md
git commit -m init
cd ../..
```

Заполните `.env`, как минимум:

```env
VK_GROUP_TOKEN=...
VK_GROUP_ID=...
VK_OWNER_IDS=...
VK_ALLOWED_USER_IDS=...
VK_MAIN_USER_IDS=...
VK_CONVERSATION_MODE=managed
WORKSPACE_ROOTS=/absolute/path/to/workspaces
OPENAI_API_KEY=...
CODEX_SANDBOX_MODE=workspace-write
CODEX_APPROVAL_POLICY=never
```

## 2. Локальная проверка

```bash
npm install --global npm@11.12.1
npm ci
npm run check
npm run dev
```

В логах не должно быть значения токена VK.

## 3. Главный чат

1. Напишите сообществу в личку `/bootstrap` с VK ID из `VK_OWNER_IDS`.
2. Убедитесь, что создана беседа `[VKodex] Main`.
3. В ней выполните `/status` и `/list`.
4. Выполните:

```text
/new smoke-repo | VK bridge smoke test
```

5. Убедитесь, что появилась отдельная беседа `[VKodex] VK bridge smoke test`.

Если `managed` возвращает ошибку, проверьте право токена на сообщения и возможность пригласить перечисленных пользователей. Для диагностики можно временно переключить `VK_CONVERSATION_MODE=auto`: тогда сессия должна остаться доступна в главном чате.

## 4. Текст и восстановление thread

1. В сессионной беседе отправьте: `Прочитай README.md и кратко перескажи.`
2. Проверьте `/status`: должен появиться Codex thread ID.
3. Перезапустите бота.
4. Отправьте продолжение: `Теперь добавь в README раздел Status.`
5. Убедитесь, что используется та же сессия и изменение сделано в том же workspace.

## 5. VK → Codex

1. Приложите фотографию и спросите, что на ней изображено.
2. Приложите текстовый или PDF-документ и попросите изучить его.
3. Проверьте создание файлов в:

```text
smoke-repo/.vkcodex/inbox/<turn-id>/
```

4. Отправьте вложение ответом на старое сообщение и отдельной пересылкой — оба варианта должны попасть в ход.
5. Проверьте, что архив не распаковывается без прямой просьбы.

## 6. Codex → VK

Отправьте задачу:

```text
Создай небольшое PNG-изображение 640x360 с текстом "VK Codex smoke test"
и положи готовый пользовательский файл в указанный bridge outbox.
```

Проверьте, что изображение пришло в VK. Затем попросите создать обычный текстовый файл — он должен прийти как документ.

## 7. Доступ и изоляция

1. Напишите боту с VK ID, которого нет в `VK_ALLOWED_USER_IDS`: ответа и запуска Codex быть не должно.
2. Убедитесь, что `git status --short` не показывает содержимое `.vkcodex`.
3. Попросите Codex вывести имена переменных окружения. `VK_GROUP_TOKEN` и `OPENAI_API_KEY` не должны присутствовать в окружении команд.
4. Попросите записать файл за пределами workspace. При `workspace-write + never` операция должна завершиться отказом, а не запросом интерактивного подтверждения.
5. Во время долгой задачи отправьте `/stop` и проверьте отмену хода.

## 8. Что записать по результатам

Сохраните:

- версию Node.js;
- версии `@openai/codex-sdk` и `vk-io` из lock-файла;
- VK API error code при неудаче `messages.createChat`;
- типы успешно принятых и отправленных файлов;
- результат перезапуска и продолжения thread;
- обезличенный лог инцидента без токенов.
